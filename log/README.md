# 授课日志规范

`log/` 记录每一次交互。这份文件是格式契约，写日志前先看它。

日志用客观视角写：学习者一律称"学习者"，不用"我"指代他。仓库公开，读者未必是当事人，
凡是需要上下文才能理解的缩写（`v1`、`v2`、单元编号）第一次出现时给出全称。

## 命名

```
YYYY-MM-DD-<单元>-<短标题>.md
```

- `<单元>`：单元编号，如 `A0`、`B02`。一次涉及多个单元或与单元无关的写 `ALL`。
- 同一天同一单元有多次交互，标题里区分，如 `2026-10-11-B02-口试-第2轮.md`。
- 标题用中文，短，不用空格。

## 头部

文件开头必须是 YAML frontmatter，字段固定这几个：

```yaml
---
date: 2026-10-11        # 交互发生的日期
unit: B02               # 单元编号；多个用逗号，如 "B02,B03"
kind: 口试              # 见下表
status: 完成            # 进行中 / 完成 / 待跟进
duration: 40            # 分钟，估的写近似值
outcome: 通过           # 通过 / 部分通过 / 不通过 / 未考核
---
```

`kind` 取值：

| 值 | 什么时候用 |
|---|---|
| `准备` | 开课前的环境、仓库、备课 |
| `授课` | 讲概念、推导、答疑式讲解 |
| `口试` | 关书抽查 |
| `批改` | 看代码、跑断言、给判定 |
| `答疑` | 学习者提问，我回答，无考核 |
| `复习` | 对错题本的间隔抽考 |
| `排障` | 环境、数据、报错之类的问题 |

`outcome` 只有口试、批改、复习会填真值，其余写 `未考核`。

## 正文小节

小节名固定，顺序固定。没有内容的小节写"无"，不要删掉小节——缺了小节说明这次交互没走完流程。

```markdown
## 目标

这次要达成什么。一句话。

## 讲了什么

要点列表。讲义在 notes/ 里，这里只记补充讲解、临时举例、被追问出来的解释。
如果全部内容都在讲义里，写"未补充，见 notes/xxx.md"。

## 学习者的产出

代码路径、运行结果、或者回答的摘要。

## 考核结果

没有考核写"未考核"，有考核用表格：

| 项 | 结果 | 备注 |
|---|---|---|
| 口试第一层 | 3/3 | |
| 口试第二层 | 1/3 | 广播规则答成"从左对齐" |
| T1 断言 | 通过 | |
| T2 断言 | 不通过 | 报错信息没指出维度 |

学习者的原话或原始答案，答错的地方如实引用，不要润色。这段是这份记录最有价值的部分。

## 暴露的问题

| 问题 | 类型 | 进错题本 |
|---|---|---|
| 广播对齐方向记反 | 概念 | 是 |
| 忘了 zero_grad | 习惯 | 是 |

类型取值：`概念` / `习惯` / `语法` / `工程`。

## 下一步

学习者要做什么（具体到文件和命令），我要准备什么。
```

## 写完之后的动作

1. 更新 `PROGRESS.md`：状态、掌握度、错题本、复习队列
2. `git add log/ PROGRESS.md work/` 加相关文件，然后 commit
3. 提交信息格式：`log(<单元>): <结果> <一句话>`，例如
   `log(B02): 口试部分通过，广播对齐方向记反`

## 别写什么

- 与学习无关的私人对话
- 密码、token、私钥路径
- 空泛的评价（"表现不错"、"进步很大"）。要评价就给指标：答对几道、哪里错、错到什么程度
