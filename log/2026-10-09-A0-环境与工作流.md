# A0 环境与工作流

跑通开发机环境，写出第一个张量脚本和第一张图，建立"讲义讲清楚、自己写代码"的节奏。

## 讲了什么

讲义之外的补充，按出现顺序记。

### 相对路径的基准是当前工作目录

`savefig("out.png")` 存到了仓库根目录，不是脚本所在的 `work/a0/`。
相对路径的基准是**运行命令时所在的目录**，不是脚本文件的位置。学习者自己找到了文件，这处没展开讲。

### 手写循环与向量化

sin.py 第一版用 `random.uniform` 取 200 个点、`x.sort()` 排序、循环调 `math.sin`。
指出这三件事在 torch 里各是一行：按个数均匀取值的函数、不需要排序、逐元素求正弦的函数。
"没排序就很难绷"是学习者自己说的，正好说明随机采样不该出现在这道题里。

### `.cuda()` / `.cpu()` / `.to()` 都不改原张量

口试 Q1 他答"根据 `cpu()` 推断，`cuda()` 应该是改变原值的"，判断反了。
在开发机实测给出证据：`x.cuda()` 之后 `x.device` 仍是 `cpu`，返回值是新对象（`x is r` 为 False）。

编辑器那句 unused return value 的意思不是"这个返回值没有用"，而是"显卡上那个张量被丢掉了"。
记忆法是 PyTorch 的命名约定：带下划线后缀的（`add_`、`zero_`）才是原地操作，`.cuda` 没有下划线版本。

### `arange` 与 `linspace`

`arange` 按步长走，个数由步长决定；`linspace` 按个数走，步长由个数决定，两端都包含。
这道题必须用 `linspace`：要正好 200 个点，用 `arange` 得自己算 `2π/199`，
而且浮点累加可能差一个点，图上就少一个数据。

### `plt.*` 的返回值要不要接

学习者自己观察到 `plt.plot` 这类调用也有 unused return 警告，并判断 A0 里不需要接，判断正确。
实测返回值：`plot` 给 list，`figure` 给 Figure，`xlabel` 给 Text。
只有走面向对象风格（`fig, ax = plt.subplots()`）时才必须接。
