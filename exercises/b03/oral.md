## 第一层：是什么

**Q1** `*` 和 `@` 分别做什么运算？各自对形状有什么要求？

<details><summary>参考答点</summary>

`*` 是按元素乘法，两个张量形状要能广播；形状相同则逐元素相乘，不同则按广播规则对齐。

`@` 是矩阵乘法，等价于 `torch.matmul`。它按"最后两维做矩阵乘、前面的维度广播"处理，
两个一维向量做点积、矩阵乘向量、矩阵乘矩阵都可以用它。

最容易混的地方：`A` 形状 `(2, 3)`、`x` 形状 `(3,)` 时，`A * x` 不报错，
它把 `x` 广播到每一行做逐元素乘，结果还是 `(2, 3)`。这不是矩阵乘向量。

</details>

**Q2** 沿某一维求和的规则是什么？`keepdim=True` 改变了什么？

<details><summary>参考答点</summary>

沿 `dim=k` 求和会把第 `k` 维消掉，结果的维度数少 1。
形状 `(3, 4)` 沿 `dim=0` 得 `(4,)`，沿 `dim=1` 得 `(3,)`。

`keepdim=True` 把被消掉的那一维保留成 1，形状 `(3, 4)` 沿 `dim=0` 得 `(1, 4)`。
维度数不变，这一维长度为 1。

不传 `dim` 表示对所有元素求和，得到一个 0 维张量。

</details>

**Q3** 点积、矩阵-向量积、矩阵-矩阵乘法在 torch 里分别用哪个函数？`@` 对应哪一个？

<details><summary>参考答点</summary>

点积 `torch.dot(a, b)`，两个一维且长度相同，结果是标量。
矩阵-向量积 `torch.mv(A, x)`，结果是向量。
矩阵-矩阵乘法 `torch.mm(A, B)`，结果是矩阵。

`@` 是 `torch.matmul` 的简写，上面三种都能做，还支持高维与广播。

</details>

## 第二层：为什么

**Q4** `A` 形状 `(3, 4)`，为什么 `A / A.sum(dim=1)` 报错？`keepdim=True` 为什么能解决？

<details><summary>参考答点</summary>

`A.sum(dim=1)` 得到形状 `(3,)`。除法的广播从最右边一维开始右对齐：`(3, 4)` 对 `(3,)`，
最后一维 4 与 3 对不上，也不是 1，于是报错。

`keepdim=True` 得到 `(3, 1)`。右对齐后最后一维是 1（可广播），第 0 维 3 与 3 相同，
广播成 `(3, 4)`，每一行除以对应的那个数。

根本原因：**想要"按行"运算，那个数必须处在与行对应的位置上**。`(3,)` 的位置语义是"最后一维"，
不是"第 0 维"。

</details>

**Q5** 三维张量的 `.T` 做了什么？为什么和二维时的直觉不同？

<details><summary>参考答点</summary>

`.T` 反转**所有**维度。形状 `(2, 3, 4)` 的 `.T` 是 `(4, 3, 2)`。

二维时"转置"恰好等于交换两个维度，所以看着像"行列互换"；三维时"交换最后两维"应当是
`(2, 4, 3)`，那要用 `.transpose(1, 2)`，不是 `.T`。

这个坑在批量数据上很常见：一批形状 `(batch, 行, 列)` 的数据想交换后两维，写 `.T` 会全反。

</details>

**Q6** 为什么需要范数？L2 范数和 L1 范数各度量什么？

<details><summary>参考答点</summary>

范数把一个向量（或矩阵）映射成一个非负数，用来衡量"有多大"。
损失函数里要衡量误差向量的大小，梯度裁剪要限制梯度的大小，都用到它。

L2 范数是各元素平方和再开根号，度量欧氏长度，对大分量惩罚更重（因为平方）。
L1 范数是各元素绝对值之和，度量曼哈顿距离，对离群值不敏感。

代码里：`torch.linalg.vector_norm(u)` 是 L2，`torch.abs(u).sum()` 是 L1。
矩阵的 Frobenius 范数是 `torch.linalg.norm(X)`，等于把矩阵展平后求 L2 范数。

</details>

## 第三层：应用与陷阱

**Q7** `torch.dot` 只接受一维向量，那 `torch.matmul` 处理高维时规则是什么？

<details><summary>参考答点</summary>

按最后两维做矩阵乘法，前面的维度按广播规则对齐。

形状 `(2, 3, 4)` 与 `(4, 5)` 相乘：后者被当成 `(1, 4, 5)`，前面的维度广播，
得到 `(2, 3, 5)`。形状 `(2, 3, 4)` 与 `(2, 4, 5)` 相乘得到 `(2, 3, 5)`，即两个批量各自做矩阵乘。

一维参与时有特殊规则：`(3, 4) @ (4,)` 得 `(3,)`，那个一维被当成向量而不是 `(1, 4)` 矩阵。

</details>

**Q8** 把矩阵每一行归一化（每行除以该行的 L2 范数）时，某一行全是 0 会发生什么？怎么处理？

<details><summary>参考答点</summary>

该行的范数是 0，除零得到 `nan`（不是报错，是静默产生 `nan`）。`nan` 一旦混进张量，
后面所有依赖它的计算都变成 `nan`，而且不会抛异常。

处理办法：给分母加一个极小的数（`norm + 1e-12`），或者把范数为 0 的行单独置 0。
前者简单，代价是那一行不再是精确的 0；后者更精确，但要额外写一行 `torch.where`。

这是数值稳定性的第一个例子，B11 会系统讲。

</details>

**Q9** `A.sum()` 不传 `dim` 会得到什么？这个默认行为在什么情况下是坑？

<details><summary>参考答点</summary>

对所有元素求和，得到一个 0 维张量（标量张量），而不是保留形状的结果。

坑在于是"静默正确"：不报错，形状却和预期不同。想按行或按列求和却忘了传 `dim`，
后面拿这个标量去做广播运算，结果会是一个形状完全不同的张量，而中间不会有任何提示。

习惯做法是求和时永远显式写 `dim`，除非确实要全局求和。

</details>
