## 必会

**Q1** BN 训练时的小批量上有哪四步？`gamma` 与 `beta` 起什么作用？

<details><summary>参考答点</summary>

1. 算均值 $\mu = \frac{1}{m}\sum x^{(i)}$
2. 算方差 $\sigma^2 = \frac{1}{m}\sum (x^{(i)} - \mu)^2$
3. 标准化 $\hat{x} = (x - \mu)/\sqrt{\sigma^2 + \epsilon}$
4. 缩放与偏移 $y = \gamma \hat{x} + \beta$

`gamma` 与 `beta` 是**可学习参数**。标准化的结果分布固定，可能限制表达能力；
它们允许网络学回来——如果 BN 无益，理论上能学出 $\gamma = \sqrt{\sigma^2+\epsilon}$、
$\beta = \mu$，把 BN 变回恒等映射。

</details>

**Q2** 输入 `(32, 64, 28, 28)` 做 BN，均值和方差在哪些维度上算？参数是什么形状？
为什么必须 `keepdim=True`？

<details><summary>参考答点</summary>

在**第 0、2、3 维**（批量、高、宽）上算，即每个通道一套统计量。
参数量是 64 个（`gamma`、`beta` 各有 64 个元素）。

必须 `keepdim=True` 是因为：不保留维度时均值形状是 `(64,)`，
输入是 `(32,64,28,28)`，直接用 `X - mean` 会按最后一维广播，算错位置甚至报错。
保留后均值是 `(1,64,1,1)`，才与通道维对齐。

</details>

**Q3** 预测时 BN 用什么统计量？`momentum=0.1` 的含义是什么？

<details><summary>参考答点</summary>

用训练期间累积的**移动平均** `moving_mean` 与 `moving_var`。

`momentum=0.1` 指**旧值保留 10%**：

```
moving = 0.1 * 旧值 + 0.9 * 当前批统计量
```

（注意与"学习率式"的直觉相反：数字越小，跟随当前批越快。）

</details>

**Q4** 残差块解决什么问题？当输入输出形状不一致时，跳跃路径要做什么？

<details><summary>参考答点</summary>

解决**退化问题**：网络加深后，训练误差反而变大（不是过拟合，是优化困难）。
学残差 $f(x) - x$ 比直接学 $f(x)$ 容易——如果理想映射接近恒等，
把残差学成 0 就行。

形状不一致时，跳跃路径上要加一个 **1×1 卷积**（步幅与主干一致），
把输入变换成与主干输出相同的通道数与高宽，才能相加。

</details>

## 了解

**Q5** DenseNet 的稠密块怎么连接每一层的输入输出？通道数怎么变？

<details><summary>参考答点</summary>

每个子块输出 `growth_rate` 个通道，然后**把输入与输出在通道维拼接**：

```python
X = torch.cat([X, Y], dim=1)
```

所以每过一个子块，通道数增加 `growth_rate`。
输入 3 通道、2 个子块、增长率 10，输出 `3 + 2×10 = 23`。

</details>

**Q6** `net.eval()` 对 BN 有什么影响？忘了调会怎样？

<details><summary>参考答点</summary>

`eval()` 让 BN 用移动平均统计量；训练模式用当前批的统计量。

忘了调的话，**预测结果会依赖同一批里的其他样本**——同一个输入换一批邻居，
输出就变了。这在部署时尤其糟糕：服务端一条一条地推理，每条都用自己当"批"，
统计量完全不对。

</details>

**Q7** 过渡层由哪些层组成？为什么 DenseNet 需要它？

<details><summary>参考答点</summary>

`BN → ReLU → 1×1 卷积（通道减半）→ 平均池化 2×2 步幅 2（高宽减半）`。

因为稠密块每层都增加 `growth_rate` 个通道，堆几个块之后通道数会膨胀得很快。
过渡层把通道数压回去、顺便把空间尺寸减半。

</details>
