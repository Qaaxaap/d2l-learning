# PDF 版讲义

markdown 版在 `notes/`。这里是排版后的 PDF，同一个内容的另一种呈现。

## 为什么另做一份

markdown 只能线性排。形状、数据流、对比这三类内容，文字和表格表达起来费劲。
PDF 可以用图、并排、分栏把这些直接画出来。

以 B22 为例，markdown 版 526 行，PDF 版 11 页。后者多出来的是图：

| 图 | 讲什么 | markdown 里对应 |
|---|---|---|
| one-hot 矩阵 | 深色格是 1，一眼看出稀疏 | 一张文字表 |
| 占用对比条 | 39 KB 对 0.5 KB，长度按实际比例 | 一句话 |
| 嵌入查表 | 矩阵第 3 行高亮，箭头指向取出的向量 | 一句话 |
| 形状流 | `(T,n)` → `(T,n,e)` → `h_n (1,n,h)` | 三行表格 |
| 贪婪的失败 | 0.048 与 0.054 并排 | 表格 |
| 三种搜索 | 贪婪 / 束搜索 / 穷举并排，中间那栏加框 | 三个小标题 |

## 配色与黑白打印

屏幕上是彩色的。黑白打印由阅读器或打印机自动转灰度，所以配色要满足一条：
**颜色只作辅助，转灰度后信息不能丢**。

| 用途 | 颜色 | 转灰度 |
|---|---|---|
| 主标题 | `#16324F` 深蓝 | 20% |
| 节标题、图节点框、代码竖条 | `#1F4E79` | 32% |
| 坑、警告、detach | `#A33A2E` 红 | 40% |
| 背景变量框 | `#C0872A` 金 | 55% |
| 嵌入查表高亮 | `#7B2D5E` 紫 | 35% |
| 各类底色 | `#EDF3FA`、`#FBEFEC`、`#FDF4E3` | 92% 以上 |

需要区分的几处，靠结构而不是颜色：

- 要点框与坑框：靠"要点"/"坑"标签，加左边框
- 5.2 两栏对比：一栏有框、一栏无框
- 8.1 三栏：中间那栏四边全框
- 条形图的两条：39 KB 与 0.5 KB，长度差 78 倍
- 6.2 的 0.048 与 0.054：数字本身不同

验证方法：

```bash
pdftoppm -png -gray -r 100 b22.pdf /tmp/x
```

逐页看。灰度下读不出来的地方，就是配色设计错了。

## 重新生成

```bash
cd notes/pdf
typst compile b22.typ b22.pdf
```

改内容改 `b22.typ`，不要改 PDF。字体用系统里的 Noto Serif CJK SC 与 DejaVu Sans Mono。

## 版面参数

| 项 | 值 |
|---|---|
| 纸张 | A4 |
| 正文宽 | 118 mm（边距左右各 46 mm）|
| 正文 | 10 pt 宋体，行距 0.85 em |
| 标题 | 17 pt / 12.5 pt，粗体 |
| 代码 | 8.4 pt 等宽，左侧 2pt 竖条 |
| 图 | 突破正文宽度到 162 mm |

正文 118 mm 是有意的。A4 满宽排一行 45 个汉字读起来累，窄一点换行更自然。
代码与图例外，它们用 `outset` 撑到纸边。
