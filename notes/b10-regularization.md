## 0 这一单元解决什么问题

B09 留下了两个判断：欠拟合要加容量，过拟合要减容量。"减容量"有两条常见路径：

1. **限制参数能取多大**——权重衰减
2. **减少单元之间的相互依赖**——丢弃法

两种手段都不改数据、不改模型结构（权重衰减连结构都不碰），只改训练过程。

## 1 权重衰减

### 1.1 做法：往损失里加一项

**$L_2$ 范数正则化**在原来的损失上加一个惩罚项。以 B06 的平方损失为例，
原损失是

$$\ell(\mathbf{w}, b) = \frac{1}{n}\sum_{i=1}^{n}\frac{1}{2}\left(\mathbf{x}^{(i)\top}\mathbf{w} + b - y^{(i)}\right)^2,$$

加上惩罚项之后要最小化的是

$$\ell(\mathbf{w}, b) + \frac{\lambda}{2n}\|\mathbf{w}\|^2,\qquad \lambda > 0 .$$

三个要点：

- **只惩罚权重 $\mathbf{w}$，不惩罚偏置 $b$**（书上的公式里没有 $b$）
- $\|\mathbf{w}\|^2$ 是权重所有元素的平方和
- **除以 $n$** 是为了让惩罚项与损失同量级，$n$ 是样本数
- **除以 2** 是为了求导后系数变整齐（平方求导出 2）

$\lambda$ 是超参数：为 0 时惩罚项不起作用；越大，学到的权重越接近 0。

### 1.2 为什么叫"权重衰减"

把新的损失代进小批量梯度下降，权重的更新式变成

$$w \leftarrow \left(1 - \frac{\eta\lambda}{|\mathcal{B}|}\right)w
- \frac{\eta}{|\mathcal{B}|}\sum_{i\in\mathcal{B}} \frac{\partial \ell^{(i)}}{\partial w} .$$

第一项里 $w$ 先**自乘一个小于 1 的数** $\left(1 - \frac{\eta\lambda}{|\mathcal{B}|}\right)$，
再减去原来的梯度。所以 $L_2$ 正则化又叫**权重衰减**——每次更新都把权重往 0 的方向
缩一点。

**这个视角很重要**：它说明权重衰减不是"在损失里加一项"这么抽象，而是**每一步都把参数
乘小一点点**。后面用 `torch.optim.SGD(..., weight_decay=...)` 时要知道它做的就是这件事。

### 1.3 书上怎么造出过拟合

书上的实验用**高维线性回归**：

$$y = 0.05 + \sum_{i=1}^{p} 0.01 x_i + \epsilon,\qquad p = 200,\ \epsilon\sim\mathcal{N}(0, 0.01^2) .$$

- **特征 200 维，真实权重全是 0.01**（很接近 0，且每维贡献都很小）
- **训练样本只有 20 个**，测试样本 100 个

20 个样本、200 个特征：参数个数是样本数的十倍，**必然过拟合**。
这是把 B09 的结论反过来用——先造出一个过拟合的场景，再比较加不加正则化的差别。

### 1.4 从零实现

三处与 B06 不同：

1. **损失里加惩罚项**。训练用的损失要返回"原损失 + 惩罚项"，两者都按批量归一化。
   书上把惩罚项定义成单独的函数，输入是权重、输出是 $\frac{\lambda}{2}\|\mathbf{w}\|^2$，
   小批量里再除以批量大小
2. **评估时不要加惩罚项**。报给读者看的训练损失与测试损失是**原损失**，
   混进惩罚项之后数值会随 $\lambda$ 变化，两个实验没法对比
3. **画图对比**。同一个数据集跑两次（`wd=0` 与 `wd` 不为 0），把两条训练损失与
   两条测试损失画在一张图上

### 1.5 简洁实现：`weight_decay`

用 `torch.optim.SGD(net.parameters(), lr=lr, weight_decay=wd)`，损失函数保持原样。
**正则化不在损失里做，在优化器里做。**

这一点容易混：书上从零实现时把惩罚项加进损失再求导，而框架把这一步收进优化器内部。
两种做法在纯 SGD 下数学等价——都等价于在梯度上加了 $\lambda w$。

**默认会衰减偏置。** `weight_decay` 作用在这个参数组里的**所有**参数上，
包括 `bias`。书上明说了这一点（"实际场景中，我们有时也在惩罚项中添加偏差元素的平方和"）。
实践中常把偏置与归一化层的参数排除在外，但那是习惯，不是规则；本书的实验不排除。

## 2 丢弃法

### 2.1 做法：训练时随机清零

对某一层的输出 $\mathbf{h}$，以概率 $p$ **清零**每个元素，再对留下的元素**除以 $1-p$**：

$$h_i' = \frac{\xi_i}{1-p} h_i,\qquad \xi_i = \begin{cases}0 & \text{概率 } p\\ 1 & \text{概率 } 1-p\end{cases}$$

$p$ 是超参数，叫**丢弃概率**。

### 2.2 为什么除以 $1-p$

为了让**期望不变**。$\xi_i$ 的期望是 $1-p$，所以

$$\mathbb{E}[h_i'] = \frac{\mathbb{E}[\xi_i]}{1-p} h_i = h_i .$$

**如果不除**，那一层的输出期望会缩小到原来的 $1-p$ 倍，后面每一层都要重新适应这个尺度，
训练会变慢。

**这个"训练时缩放、推理时不缩放"的安排叫倒置丢弃法**（inverted dropout）。
第一版书上用了这个名字。另一种做法是训练时不缩放、推理时把所有输出乘 $1-p$，
现在框架里都用前者。

### 2.3 训练与推理不对称

- **训练时**：每批都随机丢弃，同一个单元在不同批次里可能被丢也可能留下
- **推理（测试）时**：**不丢弃**，用完整的网络

书上给的理由是"为了得到更加确定性的结果"。更实际的理由是：丢弃是随机过程，
推理时我们希望同一个输入得到同一个输出；而且训练时已经把输出按 $1-p$ 放大过，
推理时不再缩放才能与训练时的期望对上。

**这件事必须由你自己声明。** torch 里 `nn.Dropout` 的行为取决于模块当前处于哪种模式：

| 调用 | 效果 |
|---|---|
| `net.train()` | 训练模式，dropout 生效 |
| `net.eval()` | 推理模式，dropout 被跳过 |

`nn.Module` 创建时默认是**训练模式**。所以评估之前要 `net.eval()`，
评估完要切回 `net.train()`。忘了切回，下一轮训练就不丢弃了，而这件事**不报错**。

**怎么知道当前是哪种模式**：`nn.Module` 有个 `training` 属性，布尔值。
`True` 表示训练模式，`False` 表示推理模式。

**怎么安全地临时切换**：先记下来，用完恢复。

```python
was_training = net.training    # 记下当前状态
net.eval()                     # 切到推理模式
# ... 做评估 ...
if was_training:               # 按原来的状态恢复
    net.train()
```

**为什么要记而不是无条件 `net.train()`**：如果这个函数可能被调用在推理模式下，
无条件切回训练模式会破坏调用者的状态。先记再恢复，函数就没有副作用。

**不要直接给 `training` 赋值。** `net.training = False` 不报错，
但它只改顶层那个对象自己的标记，**不会递归到子模块**——`nn.Dropout` 子层仍然是训练模式，
行为与 `net.eval()` 完全不同。实测：

| 写法 | 顶层 `training` | 子层 `training` |
|---|---|---|
| `net.training = False` | `False` | `True`（没变）|
| `net.eval()` | `False` | `False`（跟着变）|

`eval()` 与 `train()` 会递归处理全部子模块，直接赋值不会。所以只用这两个方法。

**换模式只影响这类"训练与推理行为不同"的层**（dropout、BatchNorm），
对 `nn.Linear`、`nn.ReLU` 没有影响。

### 2.4 为什么它能对抗过拟合

书上给的理由：由于丢弃是随机的，输出层的计算**无法过度依赖某一个隐藏单元**——
这一批它被丢了，下一批可能就轮到别人。模型于是学会用冗余的方式表示同一个特征。

**一个流传很广的类比**（两版书里都没有，原论文也没用这个词）：
丢弃法像每次训练一个不同的子网络，最后相当于对大量子网络做集成（bagging）。
这个说法能帮人记住直觉，但它不是书上给的论证，别当成书里的内容引用。

### 2.5 从零实现与简洁实现

**从零实现**要自己写丢弃函数：

```python
def dropout_layer(X, dropout):     # dropout 是丢弃概率
    ...
```

三件要做对的事：

1. **概率为 0 时直接返回输入**（不做任何事）
2. **概率为 1 时返回全零**（整个层丢掉）
3. 其余情况：生成与 `X` 同形状的 0/1 掩码，把掩码作用到 `X` 上，再除以 `1 - dropout`

掩码用 `torch.rand(X.shape) > dropout` 这类比较得到，注意**结果要转成与 `X` 同类型**。
缩放与掩码两步都在 `torch.no_grad()` 里做也可以，因为这一层没有需要求导的参数。

**简洁实现**用 `nn.Dropout(p)`，`p` 是**丢弃概率**。放在两个线性层之间：

```python
net = nn.Sequential(
    nn.Flatten(),
    nn.Linear(784, 256), nn.ReLU(), nn.Dropout(0.2),
    nn.Linear(256, 256), nn.ReLU(), nn.Dropout(0.5),
    nn.Linear(256, 10),
)
```

**注意每个 `nn.Dropout` 后面不要再跟激活函数**——dropout 作用在激活之后的输出上，
顺序颠倒不会报错，但语义变了。

## 3 实现会踩的坑

| 坑 | 症状 | 原因 |
|---|---|---|
| 评估时忘了 `net.eval()` | 测试精度偏低且每次不同 | dropout 在评估时仍然随机丢弃（2.3）|
| 评估完忘了 `net.train()` | 下一轮训练不再丢弃，且不报错 | 模式没切回去（2.3）|
| 把惩罚项算进了报告的损失 | 数值随 λ 变化，两次实验没法比 | 报告的应当是原损失（1.4）|
| 惩罚项忘了除以批量大小 | 等效 λ 随批量大小变化 | 书上除以 $n$ 是为了与损失同量级（1.1）|
| 以为 `weight_decay` 只作用于权重 | 偏置也被衰减了 | 它作用于参数组里的全部参数（1.5）|
| 丢弃函数里忘了除以 `1-p` | 输出期望缩小，收敛变慢 | 倒置丢弃法的关键一步（2.2）|
| 掩码没转成浮点 | `RuntimeError: expected scalar type Float but found ...` | 比较的结果是 bool，与 `X` 相乘要先转类型（2.5）|
| 推理时也丢弃 | 同一个输入两次推理结果不同 | 丢弃只在训练时用（2.3）|

## 自测题

1. $L_2$ 正则化的惩罚项是什么？为什么它被称为权重衰减？
2. $\lambda$ 取 0 与取很大分别是什么效果？
3. 训练用的损失里加了惩罚项，报告给读者看的损失该不该加？为什么？
4. `torch.optim.SGD` 的 `weight_decay` 会不会作用到偏置上？
5. 丢弃法里为什么要把留下的元素除以 $1-p$？
6. 训练时用丢弃、推理时不用，这件事在 torch 里靠什么控制？忘了切换会怎样？
7. 书上那个高维线性回归实验，为什么必然会过拟合？
8. 丢弃法为什么能对抗过拟合？

## 答案（做完再看）

**1.** $\frac{\lambda}{2n}\|\mathbf{w}\|^2$。把新损失代进梯度下降后，权重更新式里多出
一个"自乘 $\left(1 - \frac{\eta\lambda}{|\mathcal{B}|}\right)$"的步骤，每步都往 0 缩一点，
所以叫权重衰减。

**2.** $\lambda = 0$ 时惩罚项完全不起作用，退化成普通训练。$\lambda$ 很大时惩罚项占主导，
学到的权重接近 0，模型几乎不依赖输入。

**3.** 不该加。报告的损失要能反映模型的预测能力；混进惩罚项之后，同一个模型在不同
$\lambda$ 下的数值不同，两次实验就没法对比了。惩罚项只参与求导。

**4.** 会。`weight_decay` 作用于参数组里的全部参数，包括偏置。书上明说了这一点。
实践中常把偏置排除，但那是习惯。

**5.** 为了让这一层的输出期望不变。$\xi$ 的期望是 $1-p$，不除的话输出期望会缩小到
$1-p$ 倍，后面每一层都要重新适应这个尺度。

**6.** 靠 `net.train()` 与 `net.eval()`。`nn.Module` 默认是训练模式，评估前要切到
`eval()`，评估完要切回 `train()`。忘了切回，下一轮训练就不丢弃，而且**不报错**。

**7.** 训练样本 20 个，特征 200 维，参数个数（200 个权重加 1 个偏置）是样本数的十倍。
参数比样本多，模型能把训练集完全记住，包括其中的噪声。

**8.** 因为丢弃是随机的，每一批被丢掉的单元都不同，输出层的计算无法过度依赖某一个
隐藏单元，模型于是学会用冗余的方式表示特征。（那个"像集成很多子网络"的说法是外部的
类比，不是书上的论证。）
