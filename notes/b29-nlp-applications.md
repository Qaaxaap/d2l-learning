## 1 三个任务

### 1.1 情感分析

输入一句话，输出正面或负面。

**与语言模型的差别**：

| | 语言模型 | 情感分析 |
|---|---|---|
| 输入 | 一段文本 | 一段文本 |
| 输出 | 每个位置的下一个词 | 整句一个标签 |
| 序列长度 | 生成时可以任意长 | 输入变长，输出固定 |

**情感分析是序列分类**：多个输入时间步，一个输出。

### 1.2 自然语言推断

输入两句话，判断它们的关系。三个类别：

| 标签 | 含义 | 例子（前提 → 假设）|
|---|---|---|
| 蕴含 | 前提能推出假设 | 「两个人在跳舞」→「两个人在活动」|
| 矛盾 | 前提与假设冲突 | 「两个人在跳舞」→「两个人在睡觉」|
| 中立 | 推不出也冲突不了 | 「两个人在跳舞」→「两个人很开心」|

**「中立」是最难的一类**。模型容易把「不知道」判成「蕴含」。

### 1.3 两者的共同难点

**输入的文本长度不固定。** 一条推特 5 个词，一篇评论 500 个词。网络的输入维度不能跟着变。

下面的第 2 节解决这个问题。

## 2 变长文本的表示

### 2.1 从文本到索引

与 B19 一样：建词表，把文本转成索引列表。

```python
vocab = sorted(set(tokens))
token_to_idx = {t: i for i, t in enumerate(vocab)}
indices = [token_to_idx[t] for t in tokens]
```

**词表要留两个特殊符号**：`<unk>`（未登录词）与 `<pad>`（填充）。

- 测试时遇到词表里没有的词，换成 `<unk>`。
- 填充用的位置填 `<pad>`。

### 2.2 截断与填充

**目标**：把每条样本变成固定长度 `num_steps`。

两种操作：

| 情况 | 操作 |
|---|---|
| 长度超过 `num_steps` | **截断**，只保留前 `num_steps` 个 |
| 长度不足 `num_steps` | **填充**，末尾补 `<pad>` |

**两者合起来**叫 `truncate_pad`。

```python
def truncate_pad(line, num_steps, padding_token):
    if len(line) > num_steps:
        return line[:num_steps]          # 截断
    return line + [padding_token] * (num_steps - len(line))   # 填充
```

**为什么保留前 `num_steps` 个**：情感分析里判断依据常在句首与句尾。
中间截掉影响小。另一个做法是保留头尾各一半，按任务选。

### 2.3 为什么要固定长度

一个批量的数据要拼成一个张量。张量的形状必须整齐。

一个批量 32 条、每条填充到 50 个词，拼成 `(32, 50)`。

**填充的代价**：短句后面全是 `<pad>`，算力浪费在无意义的位置上。
优化办法是 `pad_sequence` 加 `pack_padded_sequence`，本章不展开。

### 2.4 标签与数据格式

| 量 | 形状 | 说明 |
|---|---|---|
| 输入索引 | `(batch, num_steps)` | 填充后的整句 |
| 标签 | `(batch,)` | 情感分析是 2 类，推断是 3 类 |
| 有效长度 | `(batch,)` | 每条实际有多少词，用于掩蔽 |

**有效长度不是必须的**，但有些模型要用它来忽略填充位置。

## 3 用 RNN 做情感分析

### 3.1 结构

1. 词索引过嵌入层，得到 `(batch, num_steps, embed_dim)`。
2. 过双向 RNN。
3. 取最终的隐藏状态。
4. 过全连接层输出类别数。

```python
class BiRNN(nn.Module):
    def __init__(self, vocab_size, embed_size, num_hiddens, num_layers,
                 num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_size)
        self.rnn = nn.GRU(embed_size, num_hiddens, num_layers,
                          bidirectional=True, batch_first=True)
        self.fc = nn.Linear(num_hiddens * 4, num_classes)

    def forward(self, inputs):
        x = self.embedding(inputs)
        out, h = self.rnn(x)
        # h 形状 (num_layers*2, batch, num_hiddens)
        enc = torch.cat([h[-2], h[-1]], dim=1)   # (batch, num_hiddens*2)
        return self.fc(enc)
```

### 3.2 为什么取最后一步的隐藏状态

隐藏状态是整句的压缩表示。最后一步看过全句。

**双向时取两个**：一个从前往后跑的最后状态，一个从后往前跑的最后状态。
两者拼接，得到正反两个方向的整句摘要。

### 3.3 双向的问题

双向 RNN 的后向部分要从句尾往前跑。它需要看到整句。

**序列分类可以用双向**，因为输入整句已经拿到。

**生成任务不能用**，B22 的解码器就只用了单向。

**取哪个隐藏状态**：`h[-2]` 与 `h[-1]` 是最后一层两个方向的最终状态。
多层时前面的层不要。

## 4 用 CNN 做情感分析

### 4.1 一维卷积

**一维卷积**在序列上滑动一个窗口，做加权求和。

输入 `[0, 1, 2, 3, 4]`、核 `[1, 2]`、步幅 1、无填充：

- 位置 0：`0*1 + 1*2 = 2`
- 位置 1：`1*1 + 2*2 = 5`
- 位置 2：`2*1 + 3*2 = 8`
- 位置 3：`3*1 + 4*2 = 11`

输出 `[2, 5, 8, 11]`，长度 4 = 输入长度 5 − 核 2 + 1。

**与二维卷积的关系**：一维卷积可以看成高度为 1 的二维卷积。
torch 里用 `nn.Conv1d`。

**文本上的含义**：窗口覆盖连续的几个词。卷积核学到的是「这几个词组合起来是什么模式」。

### 4.2 textCNN 的结构

1. 词索引过嵌入层，得到 `(batch, num_steps, embed_dim)`。
2. 转置成 `(batch, embed_dim, num_steps)`——`Conv1d` 要求的输入是通道在前。
3. **多个不同窗口大小的卷积**，例如 3、4、5。每个卷积后接 ReLU。
4. **时序最大池化**：对每个通道取时间维上的最大值。
5. 拼接所有通道，过全连接输出类别。

**为什么要多个窗口大小**：窗口 3 捕获三元组，窗口 5 捕获五元组。
不同粒度的模式都保留。

### 4.3 时序最大池化

**做法**：对每个通道，在时间维上取最大值。

```python
pooled = F.max_pool1d(conv_out, kernel_size=conv_out.shape[2]).squeeze(2)
```

输出形状 `(batch, 通道数)`，时间维被压掉。

**为什么是最大而不是平均**：

- 最大池化选「最像这个模式的片段」。只要句子里出现一次这个模式，就被捕获。
- 平均池化会被填充位置稀释。

情感分析里「出现一次转折词」就足以改变判断，所以用最大。

### 4.4 与 RNN 的对比

| | RNN | CNN |
|---|---|---|
| 捕捉的依赖 | 长距离（理论上）| 局部（窗口内）|
| 并行 | 差（必须逐步）| 好 |
| 训练速度 | 慢 | 快 |
| 位置信息 | 天然有序 | 靠卷积的位置 |

**实践**：文本分类上两者的效果接近，CNN 快得多。
短文本分类选 CNN，长文本或需要跨句关系时选 RNN 或 Transformer。

## 5 自然语言推断

### 5.1 三个类别与数据

数据集里每条样本是 `(前提, 假设, 标签)`。

| 数据集 | 规模 | 语言 |
|---|---|---|
| SNLI | 55 万条 | 英文 |
| MultiNLI | 43 万条 | 英文，多领域 |
| XNLI | 翻译版 | 15 种语言 |

**类别分布**：三类大致均衡。所以准确率比随机猜（33%）高多少是基本指标。

### 5.2 评价指标

**准确率**。三类均衡时它足够。

**要注意「中立」的召回率**。模型倾向于把中立判成蕴含或矛盾，总体准确率看不出这个问题。

## 6 文本对的处理

自然语言推断的输入是两句话。模型要能对比它们。三种处理方式。

### 6.1 拼接

把两句话的索引接起来：`[前提的词] + [假设的词]`。

**问题**：模型不知道从哪里开始是第二句。要加分隔符。

### 6.2 做差

前提的表示减去假设的表示。

$$\boldsymbol{v} = \boldsymbol{a} - \boldsymbol{b}$$

**含义**：差异大的地方说明两句话说的不是一回事。差异小说明可能同义。

### 6.3 相乘

前提的表示与假设的表示按元素乘。

$$\boldsymbol{v} = \boldsymbol{a} \odot \boldsymbol{b}$$

**含义**：两个位置都重要的地方乘积大。它衡量的是「共同激活」。

**实践里常用后两种**：做差与相乘再拼接起来，作为分类特征。

## 7 用注意力做推断

### 7.1 对齐

前提有 $m$ 个词，假设有 $n$ 个词。注意力的作用是给假设的每个词找出前提里最相关的词。

$$\boldsymbol{\beta}_{ij} = \text{softmax}_i\left(
\boldsymbol{w}^\top[\boldsymbol{a}_i; \boldsymbol{b}_j]\right)$$

**读法**：把前提的第 $i$ 个词与假设的第 $j$ 个词拼起来，过一个线性层得到一个分数。
对 $i$ 做 softmax，得到假设第 $j$ 个词对前提各位置的权重。

然后加权求和：

$$\tilde{\boldsymbol{a}}_j = \sum_{i=1}^{m}\beta_{ij}\boldsymbol{a}_i$$

**$\tilde{\boldsymbol{a}}_j$ 的含义**：假设第 $j$ 个词对应的「前提摘要」。

### 7.2 模型结构

1. 前提与假设各自过嵌入层。
2. 各自过一层编码（BiRNN 或 MLP）。
3. 算注意力得到对齐结果。
4. 把「假设的表示」与「对齐结果」做差、相乘，拼起来。
5. 过全连接层分类。

**做差与相乘的作用**：它们直接编码了「这个假设与前提的相关部分差多少」。

## 8 BERT 微调

### 8.1 从预训练到下游

B28 讲过 BERT 用掩码语言模型预训练。预训练完的模型可以接不同的下游任务。

**做法**：保留 BERT 主体，加一个小的分类头，在下游数据上微调。

这与 B27 的微调同一个思路：学习率要小、只换输出层。

### 8.2 输入格式

BERT 的输入不是一句话，是一个「词元序列」，带三个特殊符号：

| 符号 | 作用 |
|---|---|
| `[CLS]` | 序列开头，它的最终表示用来做分类 |
| `[SEP]` | 分隔两句话 |
| `[MASK]` | 预训练时遮住的词 |

**单句任务**：`[CLS] 句子 [SEP]`

**文本对任务**：`[CLS] 前提 [SEP] 假设 [SEP]`

**为什么用 `[CLS]`**：它在开头，通过多层注意力能看到整句。
分类时只取它的输出，接一个全连接层。

### 8.3 加分类头

```python
class BertForSequenceClassification(nn.Module):
    def __init__(self, bert, num_classes):
        super().__init__()
        self.bert = bert
        self.classifier = nn.Linear(bert.config.hidden_size, num_classes)

    def forward(self, input_ids, attention_mask):
        out = self.bert(input_ids, attention_mask=attention_mask)
        return self.classifier(out.last_hidden_state[:, 0, :])
```

`out.last_hidden_state[:, 0, :]` 就是 `[CLS]` 位置的输出。

### 8.4 三个要留意的设置

**设置一：attention_mask 不能忘。**

填充位置不该参与注意力。mask 里填充处为 0，模型会忽略这些位置。

**设置二：学习率要小。**

BERT 的预训练权重很贵。学习率用 2e-5 到 5e-5，大了会破坏。

**设置三：层数多，显存吃紧。**

BERT-base 是 12 层、1.1 亿参数。批量开大容易溢出，必要时用梯度累积。

## 9 实现会踩的坑

| 坑 | 症状 | 原因 |
|---|---|---|
| 忘了填充 | 批量拼不成张量 | 长度必须统一（2.2）|
| 填充位置参与注意力 | 效果差 | 要传 attention_mask（8.4）|
| `Conv1d` 的输入没转置 | 形状不匹配 | 它要求通道在前（4.2）|
| 时序最大池化用了平均 | 效果差 | 最大才能捕获「出现一次」的模式（4.3）|
| 双向 RNN 只取一个方向的最后状态 | 少一半信息 | 两个方向都要取（3.2）|
| 多层 RNN 取错隐藏状态 | 形状对但语义错 | 只取最后一层（3.3）|
| NLI 用拼接但没加分隔符 | 分不清两句边界 | 加 `[SEP]`（6.1）|
| 微调 BERT 学习率太大 | 效果崩 | 用 2e-5 到 5e-5（8.4）|

## 答案（做完再看）

**1.** 语言模型输入一段文本，输出每个位置的下一个词。序列分类输入一段文本，
输出整句一个标签。

**2.** 超过目标长度时截断，只留前 `num_steps` 个。不足时末尾补填充符号。
必须固定长度的原因：一个批量的数据要拼成一个张量，张量形状必须整齐。

**3.** 四步：词索引过嵌入层、过双向 RNN、取最终隐藏状态、过全连接分类。
双向时取最后一层两个方向的最终状态（`h[-2]` 与 `h[-1]`），拼接起来。

**4.** 输出长度 = 输入长度 − 核大小 + 1（步幅 1、无填充）。

例：输入 5 个元素、核宽 2，输出 $5 - 2 + 1 = 4$。

**5.** 不同窗口大小捕获不同粒度的模式。窗口 3 捕获三元组，窗口 5 捕获五元组。
都保留能让模型同时看到短模式与长模式。

**6.** 最大池化选「最像这个模式的片段」，只要句子里出现一次就被捕获。
平均池化会被填充位置稀释。

**7.** CNN 并行度高、训练快。RNN 必须逐步算、慢，但它理论上有更长的依赖范围。
文本分类上两者效果接近，CNN 快得多。

**8.** 蕴含（「两个人在跳舞」→「两个人在活动」）、
矛盾（「两个人在跳舞」→「两个人在睡觉」）、
中立（「两个人在跳舞」→「两个人很开心」）。

**9.** 三种：拼接（加分隔符区分边界）、做差（差异大说明说的不是一回事）、
相乘（衡量共同激活）。后两种常拼起来当分类特征。

**10.** `[CLS]` 放在开头，它的最终表示用来分类；
`[SEP]` 分隔两句话；`[MASK]` 在预训练时遮住词。

**11.** 三条：attention_mask 不能忘（填充位置不参与注意力）、
学习率要小（2e-5 到 5e-5）、层数多显存吃紧（必要时用梯度累积）。
