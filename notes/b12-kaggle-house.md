## 0 这一单元解决什么问题

真实数据和教科书数据不一样，区别有四个：

1. **有缺失值**（`na`）
2. **有类别特征**（街道类型是字符串，不是数字）
3. **特征量级差异大**（年份是 1900 多，面积是几十到几千）
4. **样本少**（1460 个）而特征多（79 个）

## 1 数据长什么样

### 1.1 下载与读取

数据是两个 CSV：训练集与测试集。两者都有 80 列，其中 79 列是特征、1 列是 `Id`；
只有训练集多一列标签 `SalePrice`。

训练集 1460 行、测试集 1459 行。**样本数这么少是这个任务的核心难点**——
79 个特征、1460 个样本，留一点给验证就紧张了。

读取用 **pandas**：

```python
import pandas as pd

train_data = pd.read_csv("data/kaggle_house_pred_train.csv")
test_data = pd.read_csv("data/kaggle_house_pred_test.csv")
```

`read_csv` 返回的**`DataFrame`** 是 pandas 的核心类型，可以理解为"带行列名的二维表"。
常用的几个属性与方法：

| 用法 | 作用 |
|---|---|
| `df.shape` | 行数与列数，返回 `(n_rows, n_cols)` |
| `df.columns` | 列名 |
| `df.dtypes` | 每一列的类型（`int64`、`float64`、`object`）|
| `df.iloc[0:4, 0:4]` | 按**位置**取切片（行在前、列在后）|
| `df["SalePrice"]` | 按列名取一列，返回 `Series` |
| `df.values` | 转成 numpy 数组 |

**`dtypes` 里 `object` 表示这一列是字符串**（或者混杂类型）。这一章靠它区分
"数值特征"与"类别特征"——这是第一个要建立的判断。

### 1.2 三类列

按 `dtypes` 看，79 个特征分成两类：

- **数值特征**（`int64` / `float64`）：面积、年份、房间数等。有些带缺失值
- **类别特征**（`object`）：街区、屋顶类型、地下室状况等。字符串，有的也带缺失值

**类别特征不能直接喂给模型**——模型只做数值运算。要转成数字，方法见 2.5 节。

## 2 预处理

预处理的目标：把 79 列、类型混杂、带缺失的表，变成"全部是数值、无缺失"的矩阵。

### 2.1 去掉 Id

`Id` 是每套房子的编号。它能让模型"记住"每个训练样本，但**对没见过的测试样本毫无信息量**。
留着它只会让模型学到无关的规律，所以去掉。

书上的写法是 `train_data.iloc[:, 1:-1]`：所有行、第 1 列到倒数第 2 列（去掉首列 `Id`
与末列 `SalePrice`）。

### 2.2 把训练集与测试集的特征合并

```python
all_features = pd.concat((train_data.iloc[:, 1:-1], test_data.iloc[:, 1:]))
```

**为什么要合并**：因为后面的标准化与 one-hot 都要用"全部数据的统计量"。

- 如果只用训练集算均值与标准差，测试集的数值分布可能不同，预处理就不一致
- 更关键的是 **one-hot**：训练集里没出现过的类别，测试集里可能有。分开处理的话两边列数会对不上

**这算不算数据泄漏**：测试集的特征是可以用的（比赛本来就提供），只是不能用它的**标签**。
用测试集的特征算均值不算作弊。

### 2.3 数值特征标准化

对每个数值特征减均值、除标准差：

$$x' = \frac{x - \mu}{\sigma}.$$

**为什么要做**：不同特征的量级差得远（年份 1900 多、面积几十）。梯度下降在量级不一的
特征上会走得很慢或震荡。标准化之后每个特征均值 0、标准差 1，梯度下降好走。

**这一步用的是 pandas 的 `apply`**：

```python
numeric_features = all_features.dtypes[all_features.dtypes != "object"].index
all_features[numeric_features] = all_features[numeric_features].apply(
    lambda x: (x - x.mean()) / (x.std())
)
```

`apply` 把函数作用到**每一列**上。`lambda x: ...` 里的 `x` 是整列（一个 `Series`）。

### 2.4 缺失值

两个处理点：

1. **数值特征**：标准化之后均值是 0，所以缺失值直接填 0 就等于"填均值"。
   `fillna(0)`
2. **类别特征**：不填，而是让"缺失"成为**一个类别**。`pd.get_dummies` 的
   `dummy_na=True` 会给缺失单独造一列

**为什么数值特征不"填均值再标准化"而是"先标准化再填 0"**：结果一样，后者少算一遍。
注意顺序不能反——先填 0 再标准化会把缺失值算进均值里。

### 2.5 类别特征转 one-hot

**one-hot（独热编码）**：一个取 $m$ 种值的类别特征，拆成 $m$ 列，每列取值 0 或 1。

书上的例子：`MSZoning` 有两个取值 `RL` 与 `RM`，拆成 `MSZoning_RL` 与 `MSZoning_RM`。
某样本原来是 `RL`，则 `MSZoning_RL = 1`、`MSZoning_RM = 0`。

```python
all_features = pd.get_dummies(all_features, dummy_na=True)
```

**为什么不用"编号"（RL=1、RM=2）**：那会引入虚假的大小关系。模型会以为 `RM` 比 `RL`
"大"、且差距与其它编码有关。而类别之间没有顺序。

**转换后的列数**：79 → **331**。多出来的都是 one-hot 列。

**特征数从 79 涨到 331，样本还是 1460**：参数量 331，样本数 1460，比例 1:4。
这个比例不算离谱，但也不宽裕——这也是为什么这一章要认真做交叉验证。

### 2.6 转成张量

```python
n_train = train_data.shape[0]
train_features = torch.tensor(all_features[:n_train].values, dtype=torch.float32)
test_features = torch.tensor(all_features[n_train:].values, dtype=torch.float32)
train_labels = torch.tensor(train_data["SalePrice"].values, dtype=torch.float32).reshape(-1, 1)
```

**顺序不能乱**：合并时训练集在前、测试集在后，所以按行数切回来。
一旦打乱过行序，这一步就错了，而且不报错。

## 3 评价指标：对数均方根误差

比赛用的指标是**对数均方根误差**（log RMSE）：

$$\text{log RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}\left(\log y_i - \log \hat y_i\right)^2}.$$

### 3.1 为什么取对数

**价格差同样的绝对量，在不同价位上的意义不同**：一套 10 万的房子差 1 万是 10%，
一套 100 万的房子差 1 万是 1%。

取对数之后，误差变成**相对误差**：$\log y - \log \hat y = \log(y/\hat y)$，
只与**比值**有关，与绝对价位无关。

**这在本课的目标里对应一件事**：Kaggle 这类比赛的评价指标常常不是 MSE，
而是对这种"相对误差"敏感的形式。读比赛说明时先确认指标是什么。

### 3.2 为什么要 clip

$\log$ 在 0 附近会变成 $-\infty$。模型早期可能预测出很小的值甚至负数，
直接取 log 会得到 `nan` 或 `-inf`，训练就毁了。

书上的做法是把预测值截到**不小于 1**：

```python
clipped = torch.clamp(preds, min=1.0)
```

**`torch.clamp(x, min=..., max=...)`** 把张量的每个元素限制在区间内。这里只给 `min`。
价格都是正数且远大于 1，所以截断不会影响正常预测，只防极端值。

### 3.3 实现

```python
def log_rmse(preds, labels):
    clipped = torch.clamp(preds, min=1.0)
    return torch.sqrt(((clipped.log() - labels.log()) ** 2).mean()).item()
```

**注意 `labels` 不用 clip**——真实价格都是正数。

## 4 训练

### 4.1 模型

**一个线性层**：输入 331 维，输出 1 维。

```python
net = nn.Sequential(nn.Linear(331, 1))
```

**为什么这么简单的模型**：这一章的重点在数据处理。而且房价这个任务里，
线性模型配上 one-hot 特征已经能拿到不错的分数。先有基线，再谈加复杂度。

### 4.2 优化器换成 Adam

书上一句说明：**Adam 对学习率相对不那么敏感**。

`torch.optim.Adam(net.parameters(), lr=learning_rate, weight_decay=weight_decay)`。

**它与 SGD 的关系**：Adam 仍然是梯度下降，但会给每个参数**分别**调整步长
（用历史梯度的均值与平方均值）。效果是：梯度一直很大的参数步子变小，
很少更新的参数步子变大。这省掉了大量调学习率的功夫。

完整机制在优化算法那一章（第 11 章），现在只需要知道两件事：

- 它能用
- 它不改变"损失函数在算什么"，只改变"怎么走"

### 4.3 训练函数

结构与 B06 的训练循环一样：按轮、按批、清梯度、算损失、反传、更新。
两处不同：

1. **每轮结束后用 `log_rmse` 在整个训练集上评估**，而不是平均批次损失
2. **验证集是可选的**：提交前的最后训练没有验证集（用全部训练数据）

## 5 k 折交叉验证

### 5.1 为什么需要

**样本只有 1460 个**。留出 20% 做验证只剩 1168 个训练样本，验证结果波动很大。

**k 折**把数据切成 k 份，每次拿 1 份做验证、其余 k-1 份做训练，训练 k 次，
把 k 次的验证误差平均。这样每个样本都恰好当过一次验证数据，结果更稳定。

**代价**：训练时间变成 k 倍（B09 讲过）。

### 5.2 切分函数

```python
def get_k_fold_data(k, i, X, y):
    fold_size = X.shape[0] // k
    ...
```

要点：

- **`k > 1`**：k=1 没有验证集
- **每份大小是 `n // k`**：不足的部分（`n % k`）不会被任何一份包含。
  书上这样写，意味着最后几个样本被丢掉。本课的实现要求**各份大小相差不超过 1**，
  用 `divmod` 分配余数（B09 的 T5 做过类似的事）
- **第 i 份做验证，其余拼接做训练**

### 5.3 在 k 折里选超参数

书上一组参数：`k=5, num_epochs=100, lr=5, weight_decay=0, batch_size=64`，
得到约 **0.16** 的平均验证 log RMSE。

**怎么用它**：换几组超参数，比较平均验证误差。**训练误差低但验证误差高，就是过拟合**
（B09 的判据）。

**一个常见误区**：拿 k 折的验证误差当成"最终成绩"。它是**用来选模型的**，
最终成绩要在 Kaggle 上提交才知道——而提交次数有限，所以本地估计要准。

## 6 预测与提交

选好超参数后，**用全部训练数据重新训练**一次，然后对测试集预测：

```python
def train_and_pred(train_features, test_features, train_labels,
                   num_epochs, lr, weight_decay, batch_size):
    ...
    preds = net(test_features).detach().numpy()
    test_data["SalePrice"] = pd.Series(preds.reshape(-1))
    submission = pd.concat([test_data["Id"], test_data["SalePrice"]], axis=1)
```

**提交格式**：两列，列名 `Id` 与 `SalePrice`，第一行是列名，1459 行数据。
`to_csv(..., index=False)` 是关键的——默认会把行号也写进去，多一列就提交不了。

**为什么用全部数据重训**：k 折里每折都只用 4/5 的数据。最终模型多 1/5 的数据，
效果应该更好（至少不差）。

## 7 实现会踩的坑

| 坑 | 症状 | 原因 |
|---|---|---|
| 没去掉 `Id` 就训练 | 训练误差很低、提交分数很差 | 模型靠 Id 记住样本（2.1）|
| 训练集与测试集分别标准化 | 测试集表现异常 | 两边统计量不同，预处理不一致（2.2）|
| 训练集与测试集分别 one-hot | 列数对不上报错，或列错位 | 类别集合不同（2.2）|
| 先填 0 再标准化 | 均值被拉偏 | 顺序错（2.4）|
| 类别特征直接用编号 | 训练能跑但效果差 | 引入虚假大小关系（2.5）|
| 打乱行序后再切训练/测试 | 不报错但标签错位 | 合并时靠行位置切回（2.6）|
| 忘了 clip 就取 log | `nan` 或 `-inf` | $\log 0$（3.2）|
| 提交文件带行号 | Kaggle 拒绝 | `to_csv` 少了 `index=False`（6）|
| 拿 k 折验证误差当最终成绩 | 高估或低估 | 它是选模型用的（5.3）|
| 用测试集标签算统计量 | 分数虚高 | 那是作弊（2.2）|

## 答案（做完再看）

**1.** 训练集 `(1460, 80)`、测试集 `(1459, 80)`。合并是因为标准化与 one-hot 要用全部数据的
统计量，否则两边预处理不一致、列数可能对不上。

**2.** 因为预处理必须对训练与测试**统一**。用训练集的统计量处理测试集，两边分布不同时
会引入偏差；而且 one-hot 要求两边的类别集合一致。

**3.** 数值特征标准化后填 0（等于填均值）；类别特征不填，让"缺失"成为一个类别
（`dummy_na=True`）。

**4.** 79 → 331。不能用编号，因为那会给无序的类别强加大小关系，模型会学出虚假的规律。

**5.** 取对数让误差变成相对误差（只看比值，与价位无关）。clip 是因为 $\log 0$ 会得到
`-inf` 或 `nan`，训练早期模型可能预测出接近 0 或负的值。

**6.** 样本只有 1460 个。留出 20% 验证会让训练集只剩 1168 个、验证结果波动大。
k 折让每个样本都当过一次验证数据，估计更稳。

**7.** Adam 给每个参数**分别**调整步长（用历史梯度的一阶与二阶矩），SGD 对所有参数用同一个
学习率。所以 Adam 对学习率不那么敏感。

**8.** 会多出一列行号，Kaggle 收到 3 列而不是 2 列，提交失败。
