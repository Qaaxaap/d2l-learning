## 1 机器翻译难在哪

### 1.1 一个具体例子

源句是中文「我爱学习」，目标句是英文 "I love learning"。

两句话有三处不同。

- **长度不同**。源句 4 个词，目标句 3 个词。
- **词表不同**。中文一套词表，英文一套词表。两套词表大小不一样，词之间没有对应关系。
- **顺序不同**。中文「我爱学习」逐字换成英文是 "I love study"。英语习惯说 "I love learning"。

第一处不同就把单 RNN 挡住了。

### 1.2 单个 RNN 卡在哪

B19 与 B20 的字符级语言模型，输入 `T` 个字符，输出 `T` 个预测。输入与输出的步数相同。

原因是 RNN 的结构固定。它每读一个输入就更新一次隐藏状态，每个隐藏状态对应一次输出。输入几步，输出就几步。

机器翻译要求输出步数与输入步数无关。源句 4 个词，目标句可能是 3 个词，也可能是 5 个词。单个 RNN 表达不了这个。

### 1.3 两个 RNN 分工

把任务拆成两段，每段用一个 RNN。

| 部分 | 输入 | 输出 |
|---|---|---|
| **编码器** | 输入序列 $x_1,\ldots,x_T$ | 一个**背景变量** $\boldsymbol{c}$ |
| **解码器** | 背景变量 $\boldsymbol{c}$，加已生成的 $y_1,\ldots,y_{t'-1}$ | 下一个词 $y_{t'}$ |

编码器把整个输入读完，压成一个向量。解码器从这个向量出发，逐词生成。

长度问题解决了。输入的步数与输出解耦。解码器想生成几个词就生成几个词，由它自己决定什么时候停。

背景变量（context variable）是编码器交出的那个向量。书上叫背景变量，有的资料叫上下文向量。本章统一叫背景变量。

## 2 词怎么变成向量

这一节先补一个前几章绕过去的问题。词是离散的符号，神经网络只吃数字。两者之间要做一次转换。

### 2.1 回顾 one-hot

B19 与 B20 用的是 one-hot。

做法是建一个长度等于词表大小的向量。词表有 $V$ 个词，向量就是 $V$ 维。第 $i$ 个词对应的向量，只有第 $i$ 位是 1，其余全 0。

词表是 `['a', 'b', 'c', 'd']` 时：

| 词 | 索引 | one-hot 向量 |
|---|---|---|
| a | 0 | `[1, 0, 0, 0]` |
| b | 1 | `[0, 1, 0, 0]` |
| c | 2 | `[0, 0, 1, 0]` |
| d | 3 | `[0, 0, 0, 1]` |

torch 里用 `F.one_hot(索引张量, num_classes=V)` 生成。B20 的 `to_onehot` 做的就是这件事。

one-hot 能用，前几章也确实够用。词表只有 4 个字符，或者 28 个字符。但它有两个问题，词表一大就暴露。

### 2.2 one-hot 的两个问题

**问题一，太占地方。**

词表 10000 时，每个词的 one-hot 是 10000 维。按 float32 算，一个词占 39 KB。

一个 batch 32 条、每条 10 个时间步，输入张量是 $32 \times 10$ 个词。乘上 39 KB，约 12 MB。

这 12 MB 里 99.99% 是 0。真正有用的信息只有「第几个词」这一个整数。

**问题二，词之间没有远近。**

两个 one-hot 向量的内积为：$i \ne j$ 时，两个向量没有一位同时是 1，内积是 0。

$$\boldsymbol{e}_i \cdot \boldsymbol{e}_j = 0 \quad (i \ne j)$$

意思是「猫」与「狗」的距离，和「猫」与「飞机」的距离完全一样，都是 0。

模型学不到词义的相似性。而翻译恰恰需要这个：「学习」与 "learning" 意思接近，模型该能利用这一点。

### 2.3 嵌入是什么

嵌入是一种把词索引换成向量的方法。它维护一个矩阵，第 $i$ 行就是第 $i$ 个词的向量。

$$\boldsymbol{W} \in \mathbb{R}^{V \times d}$$

$V$ 是词表大小，$d$ 是每个词的向量维数。$d$ 由人定，典型值 32 到 512。

查第 $i$ 个词，就是取矩阵的第 $i$ 行。所以嵌入的本质是**查表**。

与 one-hot 的根本差别在这里。one-hot 给每个词的向量是固定的、互相无关的。嵌入的每一行是**可训练参数**，模型训练时会调整它们，让意思相近的词靠得近。

B28 的 word2vec 专门讲怎么把这张表练出语义。那一章会看到「国王 - 男人 + 女人 ≈ 女王」这样的结果。本章不训练，只要知道这张表存在、怎么查。

### 2.4 怎么调用

torch 里用 `nn.Embedding`。

```python
emb = nn.Embedding(num_embeddings, embedding_dim)
```

第一个参数是词表大小 $V$，第二个是每个词的维数 $d$。

创建时权重随机初始化。权重的形状是 `(V, d)`，与上面的矩阵一致。

调用时传入索引张量，返回对应的那些行：

```python
out = emb(index_tensor)
```

`index_tensor` 里的每个元素必须是 `0` 到 `V-1` 之间的整数。

### 2.5 形状实测

以下是在本机测的，`V = 10000`、`d = 128`。

| 项 | 结果 |
|---|---|
| `emb.weight.numel()` | 1280000 |
| `emb.weight.shape` | `(10000, 128)` |
| 输入 `(3,)` 的索引，如 `[3, 7, 3]` | 输出 `(3, 128)` |
| 输入 `(2, 2)` 的索引 | 输出 `(2, 2, 128)` |

三条规律。

- **前面有多少个索引，输出就在前面加多少维。** 输入 `(2, 2)` 有 4 个索引，输出 `(2, 2, 128)`。
- **最后多加的那一维是 $d$。**
- **相同索引取出相同的行。** 上面 `[3, 7, 3]` 里两个 3 取出同一行。

第三条是查表的直接结果。同一个词在任何位置出现，拿到的向量都一样。

**对比占用**：词表 10000 时，one-hot 每个词 39 KB，128 维嵌入每个词 0.5 KB，差 78 倍。

### 2.6 与 one-hot 的关系

嵌入与 one-hot 后接一层线性层是等价的。

设线性层权重是 $\boldsymbol{W} \in \mathbb{R}^{V \times d}$。one-hot 向量 $\boldsymbol{e}_i$ 只有第 $i$ 位是 1，乘上矩阵等于取第 $i$ 行：

$$\boldsymbol{e}_i \boldsymbol{W} = \boldsymbol{W}[i]$$

矩阵乘法的每个输出位都是一行乘一列。$\boldsymbol{e}_i$ 只有第 $i$ 位非零，所以只剩 $\boldsymbol{W}$ 的第 $i$ 行参与。

实测验证过，两者结果完全相同。

**那为什么用嵌入。** 因为 one-hot 那条路要先造出 `(batch, V)` 的稠密矩阵，再和 `(V, d)` 相乘。嵌入直接查行，不产生中间那个大矩阵。词表越大，省得越多。

### 2.7 这一章用多少维

本章的题面统一用 `embed_size` 这个参数表示 $d$。书上取 32。

序列长度 $T$ 与批量 $n$ 加上之后，编码器的输入形状是：

| 步骤 | 形状 | 说明 |
|---|---|---|
| 原始索引 | `(T, n)` | $T$ 个时间步，每步 $n$ 个整数 |
| 嵌入之后 | `(T, n, e)` | 每个整数换成 $e$ 维向量 |
| 送进 GRU | 同上 | GRU 吃 `(seq_len, batch, input_size)` |

最后一行的 `(seq_len, batch, input_size)` 是 torch 的约定。**torch 的 RNN 默认把序列长度放第 0 维**。不加 `batch_first=True` 时，输入就是 `(seq_len, batch, d)`。

这个约定与 B21 讲 `nn.GRU` 时一致。

## 3 编码器

### 3.1 做什么

编码器是一个普通 RNN。它把整个输入序列读完，取最后一步的隐藏状态作为背景变量：

$$\boldsymbol{h}_t = f(\boldsymbol{x}_t, \boldsymbol{h}_{t-1}), \qquad
\boldsymbol{c} = q(\boldsymbol{h}_1,\ldots,\boldsymbol{h}_T)$$

书上的默认选择是 $q = \boldsymbol{h}_T$，只取最后一个。

为什么取最后一个。RNN 的隐藏状态每步都在累积信息。第 $T$ 步的隐藏状态看过前面所有输入，是信息最全的那个。

实现上是两层。先一层 `nn.Embedding` 把索引换成向量，再一层 `nn.GRU` 读序列。

### 3.2 前向返回两个东西

`nn.GRU` 的前向返回一个元组：

```python
out, h_n = rnn(x, h_0)
```

两个返回值含义不同。

| 返回值 | 形状 | 内容 |
|---|---|---|
| `out` | `(T, n, h)` | 每个时间步的输出，$T$ 个 |
| `h_n` | `(num_layers, n, h)` | 每个层最后一步的隐藏状态 |

**背景变量取 `h_n`，不取 `out`。**

`out` 是全部时间步。对单层 GRU，`out[-1]` 与 `h_n[0]` 相等，两种写法结果一样。对多层 GRU 就不一样了。`h_n` 是每层喂给下一层的最终状态，`out` 只反映最后一层。

书上取 `h_n`，因为它对层数不敏感。题面按 `h_n` 写。

### 3.3 形状逐步走一遍

设序列长 $T$、批量 $n$、词表 $V$、嵌入维 $e$、隐藏维 $h$、层数 1。

| 步骤 | 操作 | 形状 |
|---|---|---|
| 1 | 输入词索引 | `(T, n)` |
| 2 | 过嵌入层 | `(T, n, e)` |
| 3 | 过 GRU | `out` 是 `(T, n, h)`，`h_n` 是 `(1, n, h)` |
| 4 | 取 `h_n` 作背景变量 | `(1, n, h)` |

解码器需要的正是第 4 步的结果，形状 `(1, n, h)`。

**为什么这里要讲这么细。** 后面解码器的初始状态必须与编码器的返回形状对上。形状差一维，RNN 会拒绝接收。

### 3.4 背景变量是瓶颈

背景变量是**定长**的。输入序列再长，也压成一个形状固定的向量。

两个后果。

- 输入 5 个词与输入 50 个词，解码器拿到的背景变量形状相同、容量相同。
- 长句子会被压缩损失信息。50 个词的信息挤进一个 $h$ 维向量，很多细节丢失。

这是 seq2seq 的固有瓶颈。B23 的注意力机制就是为它设计的。那时不再压成一个向量，而是让解码器每一步重新看一遍整个输入。

## 4 解码器

### 4.1 做什么

解码器是另一个 RNN。在输出序列的第 $t'$ 步：

$$\boldsymbol{s}_{t'} = g(y_{t'-1}, \boldsymbol{c}, \boldsymbol{s}_{t'-1})$$

三个输入。上一步的输出 $y_{t'-1}$、背景变量 $\boldsymbol{c}$、上一步的隐藏状态 $\boldsymbol{s}_{t'-1}$。

然后过输出层得到这个词的分数：

$$\boldsymbol{o}_{t'} = \boldsymbol{s}_{t'}\boldsymbol{W}_{hq} + \boldsymbol{b}_q$$

$\boldsymbol{o}_{t'}$ 是 logits，每个词一个分数，还没归一化。

**实现上直接输出 logits，不在这里做 softmax。** softmax 交给损失函数。torch 的 `CrossEntropyLoss` 内部先做 log_softmax，自己再算一遍会重复。

### 4.2 自回归

**$y_{t'-1}$ 是上一步的输出。** 解码器用自己的输出作为下一步的输入。

这叫**自回归**（autoregressive）。B19 的字符级语言模型也是这样。

生成时只能自回归。没有标签可用，手上只有刚生成的词。

### 4.3 初始隐藏状态从哪来

解码器的初始隐藏状态来自编码器的最终状态。

编码器返回 `h_n`，形状 `(1, n, h)`。解码器的 RNN 期望的初始状态也是 `(num_layers, n, h)`。单层时两者形状相同，直接传。

### 4.4 必须 detach

传给解码器之前要 `detach()`。

```python
state = encoder_state.detach()
```

**为什么。** 编码器的计算图不需要连到解码器的训练里。

不 detach 的后果有两条。编码器的计算图会一直挂到解码器，显存翻倍。梯度会沿这条链回传到编码器，多算一遍。

本章不训练，这条仍然要遵守。T2 的断言查的就是 `requires_grad` 与计算图。

## 5 训练

### 5.1 目标函数

最大化输出序列的条件概率：

$$P(y_1,\ldots,y_{T'} \mid x_1,\ldots,x_T)
= \prod_{t'=1}^{T'} P(y_{t'} \mid y_1,\ldots,y_{t'-1}, \boldsymbol{c})$$

取负对数，得到损失：

$$-\log P = -\sum_{t'=1}^{T'} \log P(y_{t'} \mid y_1,\ldots,y_{t'-1}, \boldsymbol{c})$$

**每个时间步一个交叉熵**。整个序列求和或求平均。

### 5.2 强制教学

训练时解码器的输入有两种选择。

| 方式 | 输入 | 后果 |
|---|---|---|
| 自回归 | 上一步的**预测** $\hat{y}_{t'-1}$ | 早期预测全错，误差累积，学得很慢 |
| **强制教学** | 上一步的**标签** $y_{t'-1}$ | 每步都在正确上下文下学习 |

强制教学（teacher forcing）用真实标签当输入。

**为什么快。** 模型每一步都在正确的上下文里学习「下一个词是什么」。用预测值当输入时，早期模型预测几乎全错，输入就是噪声，学不到东西。

### 5.3 暴露偏差

训练用强制教学，预测只能自回归。两者不一致，带来一个问题。

**训练时模型看到的是正确的过去。预测时看到的是自己生成的过去。**

两者的分布不同。这个差异叫**暴露偏差**（exposure bias）。

后果。模型一旦某步出错，后面会越错越远。因为它从没在错误的上下文里训练过。

缓解办法有 scheduled sampling，训练时逐步混入预测值。本章不展开。

### 5.4 输入与标签错一位

与字符级语言模型一样：

| | 内容 |
|---|---|
| 解码器输入 | `<bos>` 我 爱 学 习 |
| 解码器标签 | 我 爱 学 习 `<eos>` |

`<bos>` 是序列开始符，beginning of sequence。`<eos>` 是结束符，end of sequence。

实现上解码器输入是 `labels[:, :-1]`，标签是 `labels[:, 1:]`。

B19 讲语言模型时做过同样的错位，只是那里没有 `<bos>`。

## 6 贪婪搜索

### 6.1 做法

训练完之后要生成。每一步取概率最大的词：

$$y_{t'} = \operatorname{argmax}_{y} P(y \mid y_1,\ldots,y_{t'-1}, \boldsymbol{c})$$

生成时每步取 `torch.argmax(logits, dim=-1)`。遇到 `<eos>` 或达到最大长度就停。

### 6.2 为什么不是最优

书上给了一个反例。假设词表有 A、B、C、`<eos>` 四个词。每个时间步的概率如下：

| 序列 | 每步概率 | 总概率 |
|---|---|---|
| 贪心得到 `A B C <eos>` | 0.5 × 0.4 × 0.4 × 0.6 | **0.048** |
| 另一条 `A C B <eos>` | 0.5 × 0.3 × 0.6 × 0.6 | **0.054** |

第二条第 2 步的概率是 0.3，不是最大。但之后每一步都更高，总概率反而更大。

**贪心在每步最优，总和不最优。** 原因在第 2 步选了不同的词之后，后面每一步的概率分布都变了。

## 7 穷举搜索

### 7.1 做法

把所有可能的序列都算一遍，取总概率最大的。

### 7.2 计算量

$O(|\mathcal{Y}|^{T'})$。词表 10000、长度 10 时是 $10^{40}$ 个序列。

不可能完成。

## 8 束搜索

### 8.1 做法

束搜索（beam search）在贪婪与穷举之间折中。它有一个超参数**束宽** $k$。

1. 第 1 步：从 $|\mathcal{Y}|$ 个词里取概率最大的 $k$ 个，作为 $k$ 个候选序列。
2. 之后每步：对 $k$ 个候选各扩展 $|\mathcal{Y}|$ 种可能。得到 $k|\mathcal{Y}|$ 个新候选，从中取总概率最大的 $k$ 个。
3. 结束：收集所有时间步出现过的候选。筛出含 `<eos>` 的那些，砍掉 `<eos>` 之后的部分。

书上用束宽 2 举例。第 1 步选出 A 与 C 两条。第 2 步对 A 与 C 各扩展 5 种，从 10 个里取前 2 个。最后得到 6 条候选序列。

### 8.2 计算量

$O(k|\mathcal{Y}|T')$。介于贪婪的 $O(|\mathcal{Y}|T')$ 与穷举的 $O(|\mathcal{Y}|^{T'})$ 之间。

**贪婪是束宽为 1 的束搜索。**

### 8.3 长度惩罚

候选序列长度不同，直接比对数概率不公平。

对数概率都是负数。项越多，总和越负。长序列天然吃亏。

**做法**是除以 $L^\alpha$ 惩罚长度：

$$\text{score} = \frac{1}{L^\alpha} \sum_{t'=1}^{L} \log P(y_{t'} \mid \cdots)$$

$L$ 是序列长度，$\alpha$ 一般取 **0.75**。

两个极端：

- $\alpha = 0$：不惩罚，倾向于选长序列。
- $\alpha = 1$：按长度完全归一化，倾向于选短序列。

**注意是 $\log P$ 除以 $L^\alpha$。** 不是 $P$ 开 $L$ 次方再加权。两者数学等价，但实现时用对数形式避免下溢。

### 8.4 实现要点

**候选用什么表示。** `(序列的 token 列表, 累积对数概率, 隐藏状态)`。

存隐藏状态是必要的。每个候选有自己的状态，扩展时要用它。

**每步怎么扩展。**

1. 对每个候选，用它的最后 token 与状态做一次解码。
2. 得到词表大小个对数概率。用 `torch.log_softmax(logits, dim=-1)` 算，或者用 `logits.topk(k)` 只取前 $k$ 个。
3. 每个对数概率加到这个候选的累积分数上。
4. 生成 $k|\mathcal{Y}|$ 个新候选。

**为什么用对数概率相加。** 概率连乘到十几步就下溢成 0。对数把连乘变成相加，不会下溢。

**什么时候停。** 某个候选生成了 `<eos>`，把它放进「完成集合」。这个候选停止扩展，其他继续。

**最终选择。** 从完成集合里按归一化分数选最高。完成集合为空时，从没完成的里选最高。

## 9 实现会踩的坑

| 坑 | 症状 | 原因 |
|---|---|---|
| 编码器背景变量没取最后一步 | 形状对但语义错 | 背景变量是 `h_n`，不是 `out`（3.2）|
| 忘了建嵌入层，直接喂索引 | 形状错误 | GRU 吃浮点向量，不吃整数（2.1）|
| 解码器输入忘了加 `<bos>` | 第一个词总是错 | 输入序列要 `labels[:, :-1]`（5.4）|
| 训练时用预测值当输入 | 收敛极慢 | 该用强制教学（5.2）|
| 解码器初始状态没 detach | 显存翻倍 | 编码器计算图连进解码器（4.4）|
| 束搜索的分数用乘积 | 下溢成 0 | 用对数概率相加（8.4）|
| 束搜索没做长度惩罚 | 总是选最短或最长 | 除以 $L^\alpha$（8.3）|
| 完成了的候选还在扩展 | 输出多出无意义字符 | 遇到 `<eos>` 就停止扩展（8.4）|
| 忘记 `<eos>` 之后要截断 | 输出带一堆填充 | 砍掉 `<eos>` 之后的部分（8.1）|
| 束搜索的候选不存状态 | 形状错误或结果错 | 每个候选有自己的隐藏状态（8.4）|

## 答案（做完再看）

**1.** 三处不同。长度不同、词表不同、顺序习惯不同。单个 RNN 的输出长度与输入绑定，做不到输出另一个长度的序列。

**2.** 一是占地方。词表 10000 时每个词 39 KB，一个 batch 大半是 0。二是词之间没有远近。任意两个 one-hot 的内积是 0，模型学不到相似性。

**3.** 维护一个 `(V, d)` 的矩阵，第 $i$ 行是第 $i$ 个词的向量，查词就是取行。权重形状 `(V, d)`，可训练。

**4.** one-hot 向量只有第 $i$ 位是 1。乘上 `(V, d)` 的矩阵，只有第 $i$ 行参与运算，结果就是第 $i$ 行。嵌入直接查这一行，不产生中间的大矩阵。

**5.** `(5, 8, 64)`。索引的形状 `(5, 8)` 保留，末尾加一维 $d = 64$。

**6.** `out` 是 `(T, n, h)`，每个时间步的输出。`h_n` 是 `(num_layers, n, h)`，每层最后一步的隐藏状态。背景变量取 `h_n`。

**7.** 背景变量是定长的。输入再长也压成一个向量，长句子会丢信息。B23 的注意力机制解决它，解码器每一步重新看一遍整个输入。

**8.** 训练时输入是上一步的标签，也就是强制教学。预测时输入是上一步的预测，也就是自回归。

**9.** 训练时把真实标签而非上一步预测当作解码器输入。代价是暴露偏差。训练时模型看到的是正确的过去，预测时看到的是自己生成的过去，两者分布不同。一旦某步出错，后面会越错越远。

**10.** 贪心每步取局部最大。第 2 步选次优可能让后面每步都更高，总概率反而更大。

书上的反例：`A B C <eos>` 总概率 $0.5\times0.4\times0.4\times0.6 = 0.048$。`A C B <eos>` 总概率 $0.5\times0.3\times0.6\times0.6 = 0.054$。

**11.** 穷举是 $O(|\mathcal{Y}|^{T'})$，词表 10000、长度 10 时是 $10^{40}$ 个序列。束搜索是 $O(k|\mathcal{Y}|T')$。束宽为 1 时退化成贪婪搜索。

**12.** 对数概率都是负数，项越多总和越负，长序列天然吃亏。$\text{score} = \frac{1}{L^\alpha}\sum \log P$，$\alpha$ 一般取 0.75。

**13.** 概率连乘到十几步就下溢成 0，所有候选分数都是 0，无法比较。对数把连乘变成相加，不会下溢。
